# ADR-0008: 오픈소스 공개

- 상태: 채택 (Accepted)
- 작성일: 2026-11-01
- 결정일: 2026-11-01
- 결정권자: 프로젝트 담당자(soonsm)
- 관련 문서: [앞으로 할 일](../roadmap.md) §1, [ADR-0004](./0004-authentication-authorization.md)(인증), [ADR-0002](./0002-deployment-packaging.md)(배포)

## 배경

Tevro는 한 조직의 설치형 Jira·Confluence 옆에서, 외부 네트워크가 막힌 내부망에 설치해 쓰는 것을 전제로 설계했다. ADR-0001~0007과 PRD에는 그 전제가 '사내', '폐쇄망' 같은 표현으로 남아 있다. 이제 다른 사람도 직접 설치해 쓸 수 있게 공개한다.

## 결정

1. **라이선스는 Apache-2.0**으로 한다. 저장소 최상위에 `LICENSE`(원문)와 `NOTICE`를 두고 `package.json`의 `license`를 `Apache-2.0`으로 한다.
   - MIT도 검토했다. 둘 다 허용형이라 쓰는 사람의 부담은 비슷하다. Apache-2.0은 기여자의 특허 허락과 특허 소송 시 허락 취소, 상표('Tevro')를 주지 않는다는 조항이 있어, 기업이 서버로 들여 쓰는 도구에 더 맞다고 보았다.
   - 저작권 표시는 `The Tevro Authors`로 한다.
2. **'회사 템플릿'을 '공용 템플릿'으로** 바꾼다. 회사가 아닌 팀이나 개인도 쓰기 때문이다. 이름만 바꾸고 권한(모두가 보고 쓰며 관리자만 고침)과 저장 값(`projects.official`, API의 `official`)은 그대로다.
3. **특정 조직의 흔적을 지운다.** 회사에서 확인할 목록(`company-checklist.md`)을 지우고, 그 안의 일반적인 내용(Jira 연동 아이디어, 로그인 확장)은 [앞으로 할 일](../roadmap.md)로 옮긴다. 특정 사이트의 Jira 판 번호는 'Jira Data Center 9.x' 같은 일반 표현으로 바꾼다.
4. **'폐쇄망' 요구는 유지한다.** 외부 CDN·글꼴 없이 동작하는 것(N-02)은 공개 뒤에도 장점이다. 코드와 지금 쓰는 문서에서는 '오프라인 설치'로 부른다.
5. **ADR-0001~0007은 고쳐 쓰지 않는다.** 결정 기록은 그때의 전제와 함께 읽어야 하므로, 그 안의 '사내'·'폐쇄망'은 '처음 설계한 대상 환경'으로 읽는다. 바뀐 것은 이 ADR이 적는다. 다만 위 2·3의 용어와 판 번호는 기록 전체에서 바꿨다.
6. **언어는 한국어와 영어**를 지원한다(웹 화면, CLI, 서버 오류 설명, README). 코드 주석과 설계 문서는 우선 한국어로 둔다.

## 공개 전에 할 것

저장소를 공개로 바꾸기 전에 [앞으로 할 일](../roadmap.md) §1의 2단계를 끝낸다. 계정 잠금은 인터넷에 올린 서버에서 남이 관리자 계정을 잠그는 데 쓰일 수 있었다. 2026-11-01에 끝냈다: 접속 주소별 실패 제한, 설정 코드가 있어야 열리는 웹 첫 설정 화면, Docker 이미지(ADR-0004 추기).

## 결과

- 외부 사용자는 Docker나 설치 스크립트로 직접 설치하고, 로컬 계정으로 시작해 필요하면 OIDC·LDAP을 붙인다(ADR-0004의 `PasswordProvider`).
- 기존 데이터와 API는 바뀌지 않는다. 화면·CLI의 문구만 바뀐다.
